
 ## 1. 프론트엔드 렌더링 방식 - SSR 과 CSR

 과거에는 서버가 HTTP 요청을 처리한 뒤 그 결과로 간단한 html 정보를 반환하면 브라우저는 그것을 단순히 화면으로 보여주는 것이 전부였다.  
 하지만 HTTP 통신 기술이 점점 발달하고 이와 동시에 웹 애플리케이션의 로직과 요구사항은 복잡해졌다.  

 또한 사용자 역시 화면을 시각적으로 보는 것에서 그치지 않고 화면을 통해 서버와 다양한 상호작용을 할 수 있게 되면서  
 화면은 보다 복잡한 데이터를 다루게 되었고 동시에 여러 로직도 같이 수행하게 되었다.  
 이처럼 화면을 생성하는 일은 점점 고도화 되고 전문 분야로 갈라져 나가게 되었는데, 이것이 현대의 프론트엔드 개발이다.  

 ### 1) SSR - Server Side Rendering

 SSR 이란 서버 사이드 렌더링의 줄임말로, 말 그대로 서버에서 화면을 렌더링 하는 것을 말한다.  
 다시 말해, 서버에서 화면을 생성하는데 필요한 모든 html 파일을 생성하고 브라우저는 전송받은 *.html 문서를 단순히 화면에 렌더링하는 방식이다.

```html
  ┌────────────┐                                                    ┌────────────┐     ┌────────────┐
  │  Client    │ ------------------------------------------------>  │  Server    │  ↔  │ Database   │
  └────────────┘                                                    └────────────┘     └────────────┘
                                                                          ↓
                                                   *.html           ┌────────────────────┐
                 <----------------------------------------------    │ View Template      │
                                                                    │ JSP, Thymeleaf     │
                                                                    │ <html>...</html>   │
                                                                    └────────────────────┘
```
 서버는 동적인 HTML 응답을 생성하기 위해 뷰 템플릿 엔진을 사용한다.    
 뷰 템플릿 엔진은 컨트롤러에서 전달받은 데이터를 템플릿에 바인딩하여 최종 HTML을 렌더링하고,    
 서버는 이를 클라이언트에게 응답으로 반환한다.


 ### 2) CSR - Client Side Rendering

 CSR 은, 말그대로 클라이언트에서 화면을 렌더링하는 것을 말한다.

```html
 ┌─────────────┐    1. request HTML /order.html  ┌──────────────┐
 │ Web Client  │   ------------------------->    │    Server    │
 │ JavaScript  │   <-------------------------    │              │
 │             │              2. order.html      │              │
 │             │   <link rel="..."> in HTML      │              │
 │             │                                 │              │
 │             │                                 │              │
 │             │  3. request linked Javascript   │              │
 │             │   ------------------------->    │              │
 │             │   <-------------------------    │              │
 │             │              4. *.js            │              │
 │             │  client logic, rendering code   │              │
 │             │                                 │              │
 │             │                                 │              │
 │             │                                 │              │
 │             │                                 │              │
 │             │         5. request Data         │              │
 │ 7.rendering │   ------------------------->    │              │
 │ with data,  │            HTTP API             │              │
 │ html code   │   <-------------------------    │              │
 │             │         6. JSON{...}            │              │
 └─────────────┘                                 │              │
                                                 └──────────────┘
```

 ☑️ 1. 클라이언트는 서버에 HTML 문서를 요청한다. (초기 요청 방식은 SSR과 유사하다.)  
 ☑️ 2. 서버는 기본적인 구조와 JS 파일 링크가 포함된 HTML을 반환한다.  
 ☑️ 3. 클라이언트는 HTML을 파싱한 후, 포함된 JS 파일을 서버에 요청한다.  
 ☑️ 4. 서버는 JS 파일을 클라이언트에게 전달한다. 해당 JS에는 클라이언트 로직과 화면 렌더링 코드가 포함되어 있다.  
 ☑️ 5. 클라이언트는 JS를 실행하며, 필요한 시점에 서버에 데이터를 요청한다. (예: 초기 로딩, 사용자 이벤트 등)  
 ☑️ 6. 서버는 요청에 따라 데이터를 JSON 형태로 반환한다.  
 ☑️ 7. 클라이언트는 전달받은 데이터와 JS를 이용해 DOM을 조작하고 화면을 동적으로 렌더링한다.

 ### 3) SSR 과 CSR 의 특징

☑️ Server Side Rendering (SSR)
  - 최종 HTML 결과를 서버에서 생성하여 클라이언트에게 전달하고 클라이언트는 HTML 을 화면에 렌더링한다.
  - 주로 데이터가 정적이고 복잡하지 않은 화면에서 사용한다.
  - Thymeleaf, freemarker, JSP 등 뷰 템플릿 엔진을 사용하여 HTML 을 생성한다.
  - 백엔드 개발자가 주로 사용한다.

☑️ Client Side Rendering (CSR)
  - 웹 브라우저에서 JS 코드를 이용해 HTML 결과를 동적으로 생성하여 화면을 렌더링한다.
  - 주로 복잡하고 데이터가 수시로 변하는 화면에서 사용한다.
  - 순간마다 화면 데이터가 동적으로 변화할 수 있다.
    - ex) google map, google calendar 등
  - React, Vue.js 같은 SPA 기술을 사용한다.
  - 프론트 엔드 개발자가 사용한다.

☑️ 어디까지 알아야 할까?
 현재에 와서 백엔드 분야와 프론트엔드 분야는 각자의 분야로 점점 더 깊어지고 전문화되고 있다.  
 따라서 백엔드와 프론트엔드를 모두 깊이 있게 잘하는 이른바 풀스택 개발자는 환상의 동물일지도 모른다.  
 어느 분야든 선택과 집중이 중요하다.
